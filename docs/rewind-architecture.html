One JSONL, Three Operations:
Role, Fork, and the new Rewind

All three endpoint functions read the agent's original session file, cut it at an exact message uuid, and write a truncated copy under a fresh id — the original is never rewritten. They differ only in where the copy goes and who resumes it. This document draws that architecture, surveys how other agentic tools solve rewind, and designs the two missing capabilities: crossing compact & clear boundaries, and marking those boundaries on the timeline rail.

Position: Cookrew should NOT build file snapshots (shadow git) — the repo's own git already covers code state, and per-machine devs can layer git-safepoint if they want. 03Compact & clear in the session file — and on the rail

fig 2 — compact is an in-file event (crossable today); clear is an inter-file event (needs lineage).

Rail marker scheme

  • ◆ compact — parsed from type:'system', subtype:'compact_boundary' (carries compactMetadata.preTokens → postTokens). Marker sits between checkpoint k and k+1; tooltip shows the compression (e.g. "999.6k → 11.2k tokens"). Checkpoints before it stay fully restorable.
  • ⇥ clear — emitted at lineage segment boundaries (file A → file B). Marker labels the previous session's short id and its checkpoint count ("12 endpoints before clear").
  • Both markers render in the rail's existing marker lane (same geometry as the focused-tag markers — the F6 alignment gate applies to any new marker row).

04Crossing clear: node-carried session lineage

fig 3 — lineage is recorded at one choke point, consumed by the rail (union) and the executor (file resolution).

The /clear adoption problem (honest edge): when the user runs /clear inside the CLI, Cookrew doesn't get an event — the CLI just starts writing a new file. Detection: SessionTurnSync already polls the watched file; when the bound file goes stale (no growth across N ticks) AND the project dir holds a NEWER file whose turns match this terminal's history tail, the sync re-resolves and rebinds through the same choke point — recording the clear in lineage and letting the rail show the new segment. Until that first re-resolve, cross-clear rewind simply offers the pre-clear segment (which is correct, not broken).
