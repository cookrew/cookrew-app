④ The gate per WorkspaceSession

Decisions of record for the remote-call lane · branch feat/gate-per-session · rebased on dev @ 8e271e5 · 2026-08-22

This note exists so that four rulings cannot be re-litigated from the spec text alone. Each of them contradicts a plain reading of marketplace-architecture.html, and each is the ruling anyway, for reasons that live in the code rather than the spec. Read this before you read §9/§10.

1 · Trust root — owner-as-issuer

RulingEach app instance issues and verifies its own call credentials.

The registry stays its own issuer. It becomes a second accepted issuer in M3 — an addition, not a migration, because decideGate takes the issuer as a parameter.

§9 says download and live call are “one protocol, two resources” and share the exact same gate state machine. That is true and it is implemented — one decision function, two bindings. What §9 does not say, and what had to be ruled, is who signs the token.

OptionWhat it costs
A · Owner-as-issuer
each instance is its own RP		 The caller obtains a credential per owner. Entitlement (“I bought this”) must be conveyed to the owner — a signed receipt, which is M3's job. M1's entitlement source is a local allow-list the owner controls. Chosen
B · Registry-as-issuer
app verifies registry-signed tokens		 Blocks ④ on hosting that does not exist: no domain, no TLS, nothing deployed. Worse, it puts an online dependency on the registry into every call — including a call between two machines on the same LAN. That stays a worse product after hosting lands. Rejected

This needed ruling before S1 because a token's issuer cannot be retconned once phones and CLIs hold credentials. The answer is the one that keeps the app self-sufficient.

2 · The decision, and the one place it lives

src/shared/gate.ts · decideGate. Transport-free, disk-free, clock-free: a pure function of facts its caller looked up. The registry binds it in registry/src/authorize.ts; the app binds it in src/main/call-authorize.ts.

Extraction proof. makeAuthorize(store, identity) kept its exact signature and the registry's A1–A4 suites (145 tests) pass untouched. That is how we know the decision moved without being altered.

3 · The C1 rule — absence is never permission

RulingThe call gate is an independent AND. It never delegates to the pairing gate, never trusts absence, and never distinguishes tiers by listener.

The mobile listener binds 0.0.0.0: the LAN tier and the internet tier are the same socket, so which listener bytes arrived on tells you nothing. And the pairing gate (C1) deliberately lets everything through when no token is configured — an escape that exists for the loopback embedder. A gate that consulted either would inherit both problems.

So decideGate is shaped against it. There is exactly one line where a credential becomes claims, and it collapses “none presented” and “presented and bad” into a single value:

const claims = credential === null ? null : issuer.verifyToken(credential)

Nothing downstream can tell those apart, so nothing downstream can ever be written to prefer one. There is no if (no credential) for a permissive branch to be added to later. The only unauthenticated 200 is public, and that is reachable solely because a resource's owner published it as such. Two further guards in the same spirit:

  • entitled is a required parameter with no default. M1's honest answer is () => null, but a binding has to write it down. A default would let a future binding be permissive by forgetting a field.
  • exportedVisibility returns null — not 'public' — for anything it cannot positively establish. An agent nobody exported is not callable.

4 · Workspace-scoped credentials, and the 403 that proves it

Today there is one pairing token for the whole app, which is why Magpie's R2 gate could not even be expressed: “this credential may call agents in playground, and only there” had no representation. CallCredentialService.mint(sub, workspace) puts the workspace inside the signed claims, and the workspace id is a required argument with no default — an unscoped-by-omission credential is exactly the shape being replaced, so there is no way to ask for one.

Genuine credential for another workspace403 workspace D4/R9. Re-authenticating with the same authenticator at the same origin cannot fix it, so a 401 would send the client round a loop that cannot terminate.

Why scope is checked at the gate and not at verification. verifyToken proves a credential is genuine and current; it deliberately does not check whether it is the right one for the resource. Folding that in would collapse the 403 into a 401 and make the branch unreachable — the exact bug a reviewer found in the registry at 467bcfd, where the mint side could only produce one scope so the refusal could never fire over HTTP.

5 · Fork granularity — per caller-conversation

RulingA fork is cut per caller-conversation, not per HTTP call.

The first call from a caller mints the fork and cuts one pin, vn. Subsequent calls on the same conversation land on that fork. R12's per-turn drawdown is unaffected.

§10 says “every import and every remote call forks a copy of the transcript.” Read literally, that is per HTTP request, and it is wrong for three reasons:

  • Latency. forkTerminal returns as soon as the card exists; the preamble lands asynchronously via injectWhenReady, after the fresh TUI boots and goes quiet. Per-call forking means a full harness boot before the first token of every turn.
  • It destroys the rail's grammar. §10's own distinction is that diamonds are session mechanics (ephemeral) and pins are published identity — permanent, named, addressable. A pin per HTTP request makes pins the more numerous and less meaningful of the two.
  • It breaks §10's own update channel. “Buyers see v3 available on the chip” presumes versions are cut deliberately, not accreted by traffic.

What is bound to what. The fork belongs to the subject and conversation, never to the token. A credential lasts an hour; a conversation may outlast it. Re-asserting mid-conversation therefore resumes the same fork instead of cutting a second version pin — which is only expressible because GateVerdict carries the verified claims on a 200.

6 · The fork is safety, not purity

§10 reads like an invariant about cleanliness: exporting or calling an agent never mutates its original session. It is not. It is a safety property, and here is the failure it prevents:

/ask is a producer. It acquires the producer lease and delivers the prompt as one bracketed paste followed by a delayed Enter, up to 1.5 s later. If that sequence is interrupted between the paste and the CR, the pasted text sits unsubmitted in the TUI's input box, where the terminal's next submission — anyone's — would carry it. ask.ts handles this by marking the terminal CONTAMINATED, and every submit-capable write then refuses until the terminal is restarted. The residue is deliberately not auto-cleared, because no control byte this code could send is proof of a clean buffer.

Therefore: without the fork, an internet caller whose connection drops at the wrong moment can brick the owner's live session — refusing the owner's own keyboard until they restart the terminal. Remote calls run against a version copy because a stranger must not be able to reach the input box the owner is typing into.

The pin lands with the call, not after it

Magpie's R4/R5 stay RED and unprovable if the call ships before the pin — a call that answers without cutting a version is a call whose §10 invariant nothing can check. S3 is therefore not splittable into “fork now, pin later”.

8 · S2 · Two decisions the route forced

RulingThe M1 ceremony proves possession of an enrolled KEY, not a passkey.

§9's whole premise is that the caller's terminal sees an ordinary teammate — so the thing on the other end is an agent or a CLI, not a human in front of an authenticator. A WebAuthn ceremony requires user presence by design: it is the right instrument for a person installing a preset and the wrong one for an agent calling a teammate every few seconds. So the caller signs a workspace-bound nonce with a key the owner enrolled. The human passkey path joins it in M3 as a second issuer, which costs nothing because the issuer is a parameter.

The nonce is bound twice over, and either binding alone would do: the server remembers which workspace issued it, and the workspace is inside the bytes the caller signs. A mistake in one is therefore not a hole.

RulingA call that passes the gate answers 501, not 200, until S4 runs the turn.

A 200 with nothing behind it is a call that answered without running, and the caller could not tell an empty reply from a finished one. That is the wrong-answer-that-looks-right this lane refuses everywhere else. 501 with a reason word is distinguishable from every refusal above it, and it turns "the gate passed" into something a test can assert without a turn existing.

Scoped by resolution, not by membership

NODE_ROUTES scopes a route by membership: the path carries a node id, and once ownerOf(id) matches, the handler is correct by construction. This route carries a name, which is only meaningful inside a workspace — so it is scoped by resolution: the name is looked up in the addressed workspace's own state and nowhere else, which makes an out-of-scope node unreachable rather than merely refused. The two mechanisms are different, and nodeIdOfRoute is asserted to decline this path so nobody later "unifies" them.

The trap avoided by name: store.nodeByName() reads focusedState. Using it would have answered for whichever canvas the owner was looking at — the defect that took /cwd off the table, and a name-addressed route is where it would be easiest to repeat.

Mounted ahead of the pairing gate, on purpose

The call route is handled before handleMobileApi. Below it, two bugs: an internet caller holds a call credential and no pairing token, so it would be asked for the very thing §9 replaces; and it would inherit C1's "no token configured ⇒ allow everything" escape. Mounted first with its own gate, neither is reachable — and a pairing token presented here buys a 401 like any other stranger's, which is what "tiers by credential, never by listener" means when the listener is 0.0.0.0 for both.

9 · S3 · A live call is never public

RulingAn app export cannot be public. Refused on write, dropped on read.

The gate keeps its public branch and the registry still uses it. This is about calls, not downloads.

§9 is right that “discovery and free download are not things identity should cost”. A call is neither. It is an anonymous stranger running compute on the owner's machine — and because §10 gives every conversation its own fork, anonymity leaves nothing to key a conversation on, so anonymous callers would have to share one transcript. Strangers reading each other's conversations is a worse outcome than a branch this store never produces.

Refusing the write is not sufficient by itself, so a public grant already on disk — from an older build, or written by hand — is dropped when read. Both are tested. If public calls are wanted later, the safe shape is a server-minted, unguessable conversation id returned on the first call: a capability rather than an absence of one, and an addition rather than a change.

What the conversation is keyed on

(workspace, agent node, subject, conversation name). The subject is in the key, not the value, so one caller cannot continue another's conversation by naming it. A caller that sends no name gets its own default — the safe shape is what happens when a client does nothing, not something it must remember to opt into. Nothing is keyed on a token, so re-asserting mid-conversation resumes the same fork instead of cutting a second version.

Ordering, and what a failure leaves behind

The pin record is computed first (pure, cannot fail), the fork is made second, the pin is persisted third, and only then is the conversation recorded. So: a fork that fails burns no version number — which matters because a skipped number makes §10's versions non-consecutive — and a conversation is never recorded pointing at a fork that was never made. A source with no completed turns is refused before anything is forked.

10 · Constraints S4 must honour

  • A 401 is a promise. A1 refused to answer 401 before identity existed, because a 401 invites a ceremony the server cannot complete and lying in a status code is still lying. The route that spends a challenge must therefore mount in the same slice as the first 401 the gate can emit. challenge() already mints real single-use nonces so that promise can be kept.
  • Unslugged /agents/… is not a route. No focus fallback, ever. Callable ⇔ addressable; a call that fell back to the focused workspace would be answered by whichever canvas the owner happened to be looking at.
  • Earn the line on the table. SCOPE_AWARE is a fail-closed allow-list and NODE_ROUTES is now the single source for scope checks — after fix/slug-seat-routes removed /cwd, “every route on this table is correct by construction” is a fact rather than a claim. The new route joins it by being genuinely scope-aware, not by being added.
  • 404, not 403, for out-of-scope existence. A scoped URL must not confirm what exists outside it — the same rule mobile-server already applies to node routes.
