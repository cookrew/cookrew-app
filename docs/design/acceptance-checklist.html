Two fixtures are deliberately not faked. The six-word fingerprint and the wallet sheet do not exist. The harness supplies the inputs they will consume and names them as missing — it does not invent a wordlist or a sheet. A fixture for a behaviour the product does not have is theatre, and it would let the acceptance run pass against nothing. The wallet fixture pays the 402 so the rest of Door A is judgeable today; A-3 is scored against the rendered sheet, never against the fixture.

Door B — authority, a live line (3 steps)

B-1Enrolment, out of bandPartly landed
Assertions
  • Both humans see the same six words for the same key — and different words for a different key. Decoy key armed for exactly this.
  • The confirm control collects a statement, not a reflex: "I COMPARED THESE · ENROL", not "Confirm".
  • The owner ticks which agents this caller may reach; the default is none.
  • An empty state that teaches: mkt.grant.empty.noexport — "Mark one in the agents list first."
B-2The remote teammate cardWall until the card lands
Assertions
  • It looks like a normal terminal card; the gating is backend-only.
  • First message forks the owner's agent and cuts exactly one pin.
  • One pin per caller-conversation, never per request — R4, already proven at the seam and mutation-killed. Acceptance re-asserts it end to end: three messages on one conversation cut one pin, and an unnamed conversation is one per caller.
  • The owner's original transcript is byte-identical afterwards.
B-3The owner stays in controlPartly landed
Assertions
  • WHO CAN CALL lists live grants.
  • Revoke stops a call mid-sentence, and says so: "Any call in progress stops."
  • The direction rule — the highest-value copy assertion on this surface. On failure the message must branch on whether the staged change added or removed access. "Access is unchanged" is reassurance when access was being added, and buries the only fact that matters when it was being taken away: "They still have access — revoke didn't complete." Same event, two voices. This is structurally the same defect as collapsing invalid into unverifiable, and it must be gated the same way: construct both directions and assert the strings differ.

Rules this run inherits

  • A wall is a finding, not a failure of mine. Missing surfaces are recorded exactly as a user meets them — a dead click, a raw body, a silent nothing.
  • Verify the surface before judging it. Two traps already cost a wrong reading: a "Not paired" modal that eats every click and is not .cr-reauth, and a remote bundle silently days behind source. Both are asserted before any measurement, and a screenshot is taken — not just a DOM query.
  • Scope every vocabulary scan to product chrome. This canvas renders the specs that define the feature; a document-wide grep finds the document, not the product.
  • Positive controls everywhere. Every "X is refused" runs beside a "Y is accepted" in the same pass, or a surface broken into refusing everything scores perfectly.
  • My own wrong readings go into the report, not into a quiet fix.
