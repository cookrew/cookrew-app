The two seams — built

① boot-in-place — SEAM BUILT ✓ (session-boot.ts, 5 tests)

The full read of the spawn path settled the open question: the PTY spawn reads no focus (PtyManager.spawn takes a terminal id, command, cwd, owning-workspace id — nothing consults focusedId). So booting a workspace in place is a plan + loop, not a store change: bootWorkspaceInPlace selects the addressed workspace's terminal nodes and calls an injected boot per node — no switch, no detach, so the owner's canvas never moves. index.ts wires this as forkTeam's bootTerminals. One app-side nit: the card lookup at spawnTracked (index.ts:667) uses focused-scoped store.node — swap to store.nodeAcrossWorkspaces so a non-focused herdr card keeps its metadata (cosmetic).

② scrubbed-env-at-spawn — SEAM BUILT ✓ (session-spawn.ts, 6 tests)

servedSpawn(raw, ctx) composes slice 1's two confinements into the one transform a served terminal's spawn passes through: wrap the command under the Seatbelt profile (sandbox-exec -f, sibling-deny so sessions are mutually invisible) AND replace the environment with the scrubbed one (HOME→sandbox, allowlist, only lent keys — the owner's ANTHROPIC_API_KEY is gone unless granted). Pure but for one injected profile write, landing inside the sandbox so END removes it. Remaining: call it from PtyManager's ensureSession for a served workspace's terminals — the integration point, app-verified.

The mount, step by step (exact sites)

  1. Construct the base + remover. base = path.join(homedir(), '.cookrew') (the tree inlines this 5×; consider a constant). remover = rmSandbox.
  2. Build the ForkEngine — now unblocked. Wrap forkTeam(teamForkDeps'(), {fromSavedTeam: templateId, dirs:[dir], worktree:true}) where teamForkDeps'.bootTerminals = (id) => bootWorkspaceInPlace({nodesOf, boot: bootTerminal}, id) (seam ①), and bootTerminal's spawn routes served terminals through servedSpawn (seam ②) — threaded as new env/profilePath options on PtyManager.spawn → the ensureSession/attachSpawn wrap point (herdr: ensureSession; tmux: attachSpawn's sh -c bootScript). .id is the workspace id. App-verified wire.
  3. Construct the seams: makeTemplateSource(svc→templateId, teams, pinResolver) (pinResolver reads the latest team pin's {version, pinId} — S1c), makeMinter({base, engine, ownerEnv: process.env, grantedKeysOf, remover}), makeConductorRoute(makeEntryTerminalLookup({nodesOf: id=>store.workspaceState(id).nodes})), makeEnder({base, cutter: callsInFlight, remover}). Then new SessionInstantiator(instantiatorDeps({...})) and a new ServedTemplates().
  4. Owner IPC: serve(serviceId, templateId, slug) / stop(serviceId) — owner-only, never on the listener (the grant-surface rule). On serve, guard a slug a live workspace already holds (store.bySlug) — the availability shadow documented in session-served.ts.
  5. The trigger, at mobile-server.ts:624: when store.bySlug(slug) misses, resolveCallScope(slug, {liveWorkspaceId, servedBySlug}). A serve result mints via admit(serviceId, accountId) — but accountId is the verified credential sub, known only inside handleCallRoutes after the ceremony. So admission sits after auth, not at the raw path split: the service (not the minted workspace) is what the caller enrols against and what the gate authorizes; the mint + route happen post-auth.
  6. Register the minted export so the gate returns 'identified': agentExports.exportAgent({workspaceId: mintedId, nodeId: orchTerminalId, visibility:'identified', callers:[sub]}) AND ensure the caller is enrolled. Two calls by doctrine, never one.
  7. Route: conductorFor(sessionId) → the orch terminal; the existing gate mount at mobile-server.ts:679 works unchanged once scope is the minted workspace id.
  8. END is already wired through the Ender: callsInFlight.cancelWhere + rmSandbox.
