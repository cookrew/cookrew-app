3 · First principles

A1 — The app is a control plane. Work happens inside the agent's process under herdr. The app only delivers, observes, records, and bills. Its cost must be proportional to in-flight work, with an idle fleet costing zero.
A2 — The transcript is the ground truth; the screen is for humans. Every agent turn lands in an append-only session file. Turn state, completion, and history come from that file. Screen scrape (attach, capture, spinner regexes) exists only for the workspace a human is looking at.
Exportability precondition (Sol r1): an agent is dispatchable only while a durable observer exists for it — a file watch, or a live scrape for scrape-only harnesses in the focused workspace. A dispatch that cannot be observed is refused at acceptance (503), never accepted into a state only the sweep can end.
A3 — The dispatch is the unit of concurrency. An exported agent takes work only through a dispatch: an identified, reserved, idempotent, billable record. One in-flight dispatch per agent (the agent process is single-threaded); N agents run N dispatches in parallel. Capacity = number of agents, not a tunable cap.
A4 — Tracking derives from work ∪ watchers; nothing is a flag. tracked = {agents with an in-flight dispatch} ∪ {agents with an observed in-flight turn} ∪ {focused workspace's agents} ∪ {agents with a live remote subscriber}. Enter on accept/observation, leave by debounced drain when the last fact lapses. There is nothing to forget, so the 38× class cannot exist.
Drain ≠ completion (Sol r1): the two decisions carry different stakes and use different evidence. Drain is cheap and recoverable (a re-watch reconciles everything), so it may fire on a quiet window — but never against a pin, a subscriber, or a positive working/blocked signal from the status feed. Completion is billing-grade and irreversible, so it requires positive finality evidence from the parser (an end-of-turn marker or a next-user boundary) plus prompt identity — quiet time alone closes nothing.
A5 — One inventory, pushed or batched — never per-pane forks. All herdr questions on periodic paths are answered from the push status feed or one batched snapshot per server per tick. Sync process spawns are reserved for lifecycle actions (create/kill/attach), which are rare and human-initiated.
A6 — Reads are incremental. Session files only append, except rewind/rotation. Observe with stat; on growth read only the delta; full re-parse only when the file shrank or rotated. Cost per turn is O(bytes of that turn), independent of history size.

7 · Concurrency semantics, stated precisely

  • Per agent: one in-flight dispatch (the agent process is a single conversation). Second dispatch → 409 busy; replay of the same idempotency key → 200 always.
  • Per fleet: N agents run N dispatches concurrently. No workspace cap, no scheduler mode. The only global limits are billing-side (pending-quote caps, spend caps).
  • Observation under concurrency: tracked agents are observed from their files (I3) — concurrent turns cost ΔS each, not fleet inventories. The one shared snapshot per server serves everyone's pane questions (I2).
  • Failure: herdr dying interrupts (never fails) every in-flight dispatch it hosted; the app survives (process guards) and hydrate closes honestly on restart. Panes are never killed by tracking decisions.
