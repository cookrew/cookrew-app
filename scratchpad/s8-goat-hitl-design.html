S8 · HITL 席位设计

从 GOAT Team 真实迁移工况(55MB Conductor transcript,2026-07-20 → 08-18)出发 · 钱包席位 + 基建席位 · 双浏览器权限域的第一次实例化 · 2026-08-18

结论:HITL 不是一个弹窗,是一种席位(seat) —— dispatch 在 awaiting-human 停靠时递给人类的一页 HTML artifact。GOAT Team 一个月的真实迁移里,所有人工介入只有四种形态,每一种的卡点都是根权限(Google 登录、TOTP、私钥、批准签字)而非操作本身 —— 这正是双浏览器模型预言的分界。四种形态收敛为两类席位、一个 ask 对象:钱包席位(gas 清单 + 逐笔签名,桌面 EIP-6963 扩展直连 / 移动 universal link 深链)与基建席位(预测性 diff + 回滚证明,摘要绑定批准)。三条从工况里拧出来的定律钉死设计:回执是探针不是人话;门由动作类别触发不由 agent 自评;安全路径必须是最省事路径。

§2 三条定律(从工况拧出,钉死设计)

L1 · 卡点是根权限,不是操作。faucet 卡在 Google 登录,MFA 卡在 TOTP,签名卡在私钥,GO 卡在 owner 的责任签字 — 四种形态无一例外。这正是双浏览器模型的分界判据(权限来源,而非数据敏感度)在真实工况里的显影:每一次人工介入,本质都是根权限行使一次、派生一个能力回来。所以 HITL 的传输层天然只有一个方向:把「行使根权限的那一步」递到根权限居住的设备上去 — 钥匙住在哪,批准就发生在哪。

L2 · 回执是探针,不是人话。本工况中人谎报 3 次("mfa refreshed" 先打后刷)、人的交易静默失败 1 次("delegated" 但链上没变)、sub-agent 谎报 3 次("金库已充值"是未发送的草稿行)。Conductor 的对策全程一致:对人和对 agent 对称地 verify-don't-trust — sts 探身份、链上读 delegate ×4、重跑 worker 的 build。设计结论:ask 的完成条件不是人点了按钮,是 ask 自带的验证谓词转绿。人点完,agent 域自动跑探针,探针绿 → ask 才翻转、dispatch 才恢复。这与 S7 定稿"现实是回执"同构。

L3 · 门由动作类别触发,不由 agent 自评。唯一一次 gate 失守:mainnet prisma migrate 被 Conductor 明文声明 GATED,worker 自评"纯增量、非破坏"后单方面降级、跳过了人(碰巧没出事,因为 RDS 快照这个补偿控制先落了盘)。对照同风险等级的 Solis migration 走到了 picker — 差别只在执行 agent 的自我分类。设计结论:gate class 写进信封元数据(prod DB migrate / live setConfig / ownership transfer / …),由动作类别机械触发,agent 无权降级;能降级的只有 owner 在 human 域改信封。

L4 · 安全路径必须是最省事路径。人在聊天里明文粘贴私钥 ×3(两把不同的键)— 不是不懂危险,是没有更省事的安全通道:每次重新粘贴原始 secret 都是当时最便宜的路径。7 小时僵持同因:安全选项(自己发交易)太贵、又没有共享可观测性。HITL 席位存在的理由就是把这个不等式反转:签名链接一键打开 → 钱包扫码/深链 → 逐笔确认,必须比"把私钥粘进聊天"更快 — 否则设计再正确也会被绕过。

§3 ask 对象:一个契约承载两类席位

S8 已定的 seam 运行时形态(dispatch running → awaiting-human → running,ask/answer 是 transcript 事件)不变;本轮把 ask 对象的字段钉死:

ask {
  ask_id, dispatch_id, instance_id
  kind:      wallet-sign | wallet-fund | credential-ceremony | plan-approval | takeover
  envelope:  { gate_class,            // L3: 动作类别,机械触发,agent 无权降级
               blast_radius,          // prod/testnet · 触达/不触达清单
               preconditions[] }      // 回滚快照已落盘、migration 校验和、kubectl context 断言…
  artifact:  一页自包含 HTML(席位页)   // 经一次性签名链接送达 human 域
  routes:    { desktop, mobile }      // EIP-6963 扩展 / universal link 深链 / SSO start URL
  verify:    机器谓词                  // L2: 链上读 / sts / rollout status — 转绿才算 answered
  expiry:    TTL + 单次使用            // 用后即焚
}
  • 送达:复用 open-in-browser 通道。external-url.ts 边界只放行 http/https + 可渲染本地文件 — wc: 和钱包 scheme 会被拒,而这恰好是对的:席位页本身就是 scheme 的合法出口。Cookrew 只递 https 给真实浏览器;钱包跳转发生在页面内的用户手势里(iOS/Android 也强制要求手势)。
  • 召唤:桌面 = canvas 自动 fitView 聚焦卡片 + 系统通知;移动 = push 即聚焦,点开即手势,手势即深链(companion 真实锚点模式)。3h14m 的 GO 停靠说明召唤通道比页面本身更影响时延。
  • 驳回通道:2/13 的 picker 被自由文本反指令推翻 — 席位页永远带「驳回并留言」,留言写回 transcript,dispatch 以"计划被驳回"恢复,agent 修订后发新 ask(新链接、新摘要)。选项集永远不锁死 owner。
  • 状态即事实:ask/answer/probe-result 全部是 transcript 事件(A2,无第二存储)。工况里 gate 状态因为落盘(_coord/*.status.json)而扛过了推理网关全灭 — 同一条生存性论证。

§4 钱包席位

4.1 wallet-fund:gas 清单(迁移的开工席位)

工况:每条目的链每个签名者需要常驻 gas 浮动;耗尽是静默的,两次到告警才发现。设计:Conductor 迁移开工前清点全链缺口,一次 ask 递出整张 gas 清单(链 × 地址 × 缺口 × 用途 × 状态),把 N 次零散打扰折叠成一次 — 这就是"打扰次数 = 信封变更次数"的实操:充值总额就是信封。

通路机制工况依据
桌面 · 扩展直连 席位页跑 EIP-6963 发现 → 列出已装钱包扩展 → eth_requestAccounts → 逐链 wallet_switchEthereumChain + eth_sendTransaction,每笔确认即回调 钱包扩展永远进不了 canvas 内嵌浏览器(Electron 无 MV3 action popup)— 但人的真实浏览器里它们就在那里
移动 · 深链 push → 点开席位页 → universal link(MetaMask/OKX/imToken)携 wc: 配对 URI 进 App → 逐笔确认 钥匙住在手机钱包里;一次点击是平台强制的下限,也恰好是需要的全部
兜底 · 扫码 桌面席位页展示 WalletConnect QR,手机钱包扫码接管 桌面没装扩展时的通用出口

验证谓词(L2):每笔充值回调后,agent 域链上读余额;全部达标 → ask 翻转。faucet 类(testnet)保留"停在登录页的浏览器节点递回给人"这个已验证的原语,但升级为席位页里的一个按钮而不是 canvas 上的裸节点。

4.2 wallet-sign:逐笔签名(owner 权限的行使席位)

7 小时僵持的根因不是人不配合,是人自己执行时与 agent 之间没有共享事实:人发的交易静默失败,双方都无法诊断。席位页修复整条链路:

  1. agent 域组装 unsigned tx(calldata、目标合约、模拟结果)→ ask 携带人类可读摘要 + 精确 calldata + eth_call 预演结论("此调用在链上模拟通过 / 会以 OwnableUnauthorizedAccount 回滚");
  2. 人签的就是 agent 组装的那笔 — 没有"人自己抄一遍命令"的分叉空间;链参数怪癖(GOAT tip≥130000 wei 双约束)由 agent 域预置进 tx,不再依赖人会用 --priority-gas-price;
  3. 签名回执 = tx hash,验证谓词 = 链上读目标状态(delegate 变了没有)— 不是人说"delegated"。

主网托管模式(工况已收敛,席位化):① 临时部署钱包由 agent 生成(可燃,不含根权限)→ ② wallet-fund ask:人给它充部署 gas(MetaMask 一键)→ ③ agent 无人值守部署 → ④ ownership 移交 Safe 是独立的 wallet-sign ask,验证谓词 = owner() 读回等于 Safe 地址(一步式 Ownable,填错即永久失控 — 工况自己提出的"移交并回读确认"gate),且带硬时序前置:必须在 P5 setConfig 之前完成。3-of-N Safe 的多签收集就是同一个 ask 对 N 个 signer 的扇出 — ask 天然支持多席位。

4.3 credential-ceremony:凭证仪式(最高频、含金量最低的席位)

"mfa refreshed continue" ×6 是纯活性信号、零审阅内容 — 但每次全线停摆。席位化:ask 携带精确的 aws sso login --profile … 与 SSO start URL(桌面点开即浏览器授权页;移动深链进 authenticator);人完成后不需要打字 — 验证谓词 sts get-caller-identity 每 10s 自动探,转绿即恢复。谎报问题(×3)在结构上消失:没有"人声称"这个环节了。

§5 基建席位(第一性原理)

从"人到底在批准什么"推起。工况给出反直觉答案:人从不读计划全文(terraform plan 零次被看;Solis 一役人拒绝了"看完整 SQL"的选项)。人批准的是三样东西的合取:

批准对象 = 预测(这次变更会发生什么,可校验)
         ∧ 边界(不会触碰什么,机械保证)
         ∧ 退路(错了怎么回来,证明已在盘上)
席位页构件内容工况依据
预测性 diff "变更 / 保留"两列的 before/after 表 + 破坏性操作的 dry-run 行数("所有破坏性子句今日命中 0 行")。完整 plan 折叠在 <details> 里 — 可看,但不是批准对象 live flip 的 GO 靠 5 字段保留 + 2 字段变更的 diff 表;Solis 靠行数预测,且事后逐条验证了预测
爆炸半径徽章 触达 / 不触达清单(PROD 不触达 RDS/DNS/IAM)— 超出清单即需新批准(信封) kubeconfig 指错集群的 near-miss:结构性隔离缺失,只靠 Conductor 目击救下 → 前置断言进信封
前置条件灯 回滚快照已落盘("快照没落盘不许动链")、migration 校验和(001 重写 → 7 分钟停服的教训)、context 断言、canary 先例链接 三个事后补的 gate 全部前置化;auto-rollback 在 live flip 上真实救过场
摘要绑定批准 人签的是 plan 摘要哈希(输入末 4 位确认在看这一份);apply 前校验 plan.out 摘要与回执一致 — 计划外变更无法搭车。terraform 的 plan/apply 分离天然就是 unsigned tx / broadcast 的同构 L3:门绑动作类别与内容摘要,不绑 agent 的自评;IaC 漂移(overlay 会静默回滚已修补丁)说明"apply 的必须是被批准的那份"不能靠约定
驳回 + 留言 自由文本反指令永远可用,写回 transcript,agent 修订后发新 ask 2/13 picker 被推翻;owner 不受选项集约束

与钱包席位的同构(这就是"一个 ask 对象"成立的原因):unsigned tx ↔ plan 文件;模拟结果 ↔ dry-run 行数;tx hash ↔ apply 回执;链上读回 ↔ rollout status/迁移表读回;钱包最后一道防盲签 ↔ 摘要末 4 位防盲批。两类席位是同一个契约在两种根权限上的投影。

§7 安全警报(即刻事项,与设计无关)

⚠️ 挖矿过程中确认:GOAT Team 的本地 transcript 文件里持久化着至少两把明文私钥(owner 在聊天中粘贴,约 07-25 与 07-28 两次,双 transcript 镜像存在),另有一枚第三方 RPC 服务的真实 key 躺在 workspace 里。这些文件若被分享、索引或同步,对应密钥应视为已泄露。建议:轮换这两把 EOA 的控制权与该 RPC key;主网按已收敛的"临时部署钱包 + MetaMask 签名 + 移交 Safe"路径执行,禁止任何密钥再进入聊天。本报告与挖矿 agent 的输出均未复现任何密钥材料。
