[P0] Terminal transitions still advance and release when their ledger append fails
WHERE: src/main/dispatch.ts:988-1011,1068-1087; tests/dispatch-hardening.test.ts:162-181; scratchpad/v5-export-concurrency.html:224 (I7)
CLAIM: The submitted row is now fail-closed, but every later billing-grade transition remains fail-open: memory advances, the agent reservation is released, and clients can observe a terminal state even when no durable transition exists.
EVIDENCE: `update` calls `write(next)` and unconditionally calls `release(next)` for terminal states. `write` installs `next` in memory before attempting persistence twice and only logs after both failures. The hardening test explicitly asserts that memory advances on failed transition appends.
