[P0] Partial owner input can be combined with a newly admitted dispatch
WHERE: src/main/ask.ts:297-311; src/main/turn-tracker.ts:1590-1611; src/main/dispatch.ts:1473-1506,1659-1697
CLAIM: `ownerSubmit` acquires the producer lease only when the current byte chunk contains a submit, so ordinary canvas typing leaves real owner text in the shared TUI input box while a dispatch remains free to acquire the lease and submit into that same box.
EVIDENCE: `ownerSubmit(session, "owner text")` takes the non-submitting branch and calls the unleased `session.write`; `guardOwnerInput` explicitly allows that typing while a dispatch is merely armed. Before the owner sends Enter, a dispatch can be accepted and its native or fallback leg can acquire the free lease. The dispatch code itself establishes that herdr and the fallback type into the same TUI box. The fallback paste therefore appends consumer text to the owner's buffered text and its CR submits the combined principal input; the source-tagged dispatch CR is exempt from owner preemption. Native delivery has the same shared-box premise used by the contamination guard. This executes work that is neither the exact dispatch prompt nor solely owner work and destroys correlation/billing identity.
FIX: Model input-buffer ownership, not only the final submit window. Acquire an owner editing reservation on the first meaningful owner byte and hold it until submit, verified clear, or terminal retirement; dispatch admission/delivery must refuse while that reservation or a nonempty owner buffer exists. Alternatively route the desktop composer as one atomic full-prompt submit and prohibit split owner construction on exportable terminals.

[P1] Retiring a generation does not abort the native herdr prompt child
WHERE: src/main/herdr-agent-wait.ts:97-117,147-150; src/main/dispatch.ts:1504-1516; src/main/producer-lease.ts:111-121; src/main/index.ts:1165-1172
CLAIM: Lease retirement prevents a late child from blocking a reborn terminal, but the `herdr agent prompt --wait` process itself has no abort seam and can remain for the full two-to-ten-minute caller timeout after terminal removal, rebind, backend death, or dispatch interruption.
EVIDENCE: `runCli` creates an `execFile` promise and exposes neither its ChildProcess nor an AbortSignal. `retireTerminal` and backend-death handling invalidate bookkeeping only; they cannot kill the wait. A backend outage with N in-flight prompts therefore leaves N CLI children, pipes, callbacks, and promises alive while replacement work can start. FIX: Return a cancellable prompt handle or accept an AbortSignal, store it per delivery/ask generation, and terminate the CLI child from interrupt, release, terminal retirement, and backend death. Bound TERM with a KILL fallback and test that process count returns to baseline immediately.

[P1] Malformed successful admission output publishes an empty inventory without backoff
WHERE: src/main/herdr-host-multiplexer.ts:92-112,484-520
CLAIM: The refresh's parse-failure backoff is unreachable because `parsePaneList` converts malformed JSON and herdr error envelopes to `[]`; an exit-0 bad response is published as a successful empty inventory and resets backoff.

[P1] Admission pre-warm still performs unbounded synchronous herdr forks on Electron startup
WHERE: src/main/pty.ts:853-860; src/main/herdr-host-multiplexer.ts:193-210,443-451,523-526

EVIDENCE: `primeAdmissionCache` calls `readPanes`; `readPanes` calls `available` and then the synchronous runner. Neither `createHerdrRunner.run` nor `.probe` has a timeout. [P1] Overlay compaction still puts an O(total history) rewrite on the hot tail flush

[P1] A post-rename fsync failure can desynchronize the annotation epoch cache
WHERE: src/main/turn-annotations.ts:235-288,501-527,550-560,582-612
CLAIM: `writeFileAtomic` throws if parent-directory fsync fails after `renameSync`, but a best-effort annotation compaction treats the failure as if no new snapshot were published and leaves the in-memory epoch old even though the target file already carries epoch+1.
EVIDENCE: On the threshold update, log ops at epoch E are appended and applied. `persistSnapshot` renames a complete epoch E+1 snapshot, then directory fsync throws; line 601 never updates `epochs`, `maybeCompact` ignores the false result, and `update` returns true. A later update stamps its op with cached epoch E. A hard crash after that append but before/retrying the next compaction reopens the store on snapshot E+1, which ignores the new E op, losing underivable title/seen/scroll state. On any compaction failure, hold a `pendingFull` generation barrier so no incremental op can be stamped until the snapshot/epoch state is reconciled. Add the exact rename-success/dir-fsync-failure/new-update/crash/reopen test.

[P1] EACCES and EPERM are incorrectly treated as successful directory durability
WHERE: src/main/turn-annotations.ts:203-211,277-287
CLAIM: The tolerated directory-fsync set includes permission failures, so the helper can claim a durable atomic replacement when it was denied the operation required to make the rename durable.
EVIDENCE: EACCES and EPERM do not mean the filesystem lacks directory fsync; they can mean this process is not allowed to open/fsync that directory. A process may have enough write/execute permission to rename an entry while lacking read/open permission for the directory. In that state the target is renamed, parent fsync fails, the error is swallowed, and callers discard retry state even though a crash can lose the directory entry. Avoiding an infinite retry is an operational concern, not evidence of durability.
FIX: Tolerate only errors that positively denote unsupported directory fsync on the platform/filesystem (for example ENOTSUP/EINVAL where documented). Propagate EACCES/EPERM, retain dirty state, and surface a loud persistent storage fault.

[P1] Desktop owner input refusals are silent and can last for the entire native turn
WHERE: src/main/ask.ts:123-144; src/main/herdr-agent-wait.ts:56-76; src/main/pty.ts:428-448; src/main/index.ts:2176-2179
CLAIM: A native owner ask holds the producer lease until `agent prompt --wait` observes idle/done/blocked, while the renderer IPC ignores `PtySession.write`'s refusal result, so every desktop keystroke during that potentially minutes-long turn silently disappears.

[P2] Retired terminal ids retain hidden lease and generation entries for process lifetime
WHERE: src/main/producer-lease.ts:99-121,201-206
CLAIM: `retire` increments `generations` and clears contamination but never deletes the old `holds` entry, and neither map has a reclamation path for permanently removed terminal ids.
EVIDENCE: `liveHold` merely hides a generation-mismatched hold. A new acquire for the same id overwrites it, but a removed UUID that is never reused leaves both the stale hold and generation entry in the process-wide singleton forever. Repeated create/delete cycles therefore grow the maps monotonically; late child settlement no longer needs the retained hold because holder/generation invalidation has already happened.
FIX: Delete `holds[terminalId]` during `retire`. Add a final forget/reclaim operation for ids known never to be reused, while preserving a small generation tombstone only as long as stale asynchronous holders can still return.

[P2] `count()` disagrees with the reader for orphan or malformed overlay lines
WHERE: src/main/turn-store.ts:234-296,357-388
CLAIM: The logical reader preserves an orphan overlay as a record, but `count()` blindly subtracts every marker-shaped physical line as though it superseded an existing base record.
EVIDENCE: `readLines` explicitly pushes an overlay whose base index is absent, yielding (for example) base index 1 plus orphan overlay index 5 as two records. `count` sees two physical lines and one marker and returns one.
