owner 裁定(2026-08-17):停止对抗循环,以简洁与可扩展为纲整理定稿。四轮设计评审的结构性收获保留, 增生的证明机器剪除。原则:效果全部可观测时,现实就是回执;受信本地的数十实例规模,不配拥有百万级机器。

1 · 保留的骨架(四轮买来的,每条一句话)

① D0 双闸:COOKREW_INSTANCE_FACTORY=1 门公共路由(关=404);caretaker(hydrate+清理)永远启动。受信本地专属,OS 隔离前不对外
② v1 单 agent,恰一不变量:manifest 恰含一个 terminal = entry = 唯一 scope/boot;多余即拒
③ 计划先行:创建前预分配全部 id(instance/workspace/完整UUID herdrSession/node),先落一行 intent,再做效果
④ 克隆规格:保留 uuid/parentUuid 图、只重写 session/路径身份、摘要校验、黄金源在扫描树外、resume 后 rebind 后继
⑤ manifest 内容寻址:digest 定版(含 worktree commit+tree SHA、专属保留 ref、价卡);发布门:compact 水位、单档≤5MB、禁 submodule/LFS/filter
⑥ 阻塞 201 + 幂等 key;token = keyId+secret 索引鉴权;scope 只含实例 agent
⑦ 屏障先于意图:destroy 先同步关准入再落盘意图;回滚走 v5 原语序,疑则留债,永不删活资源最后所有者
⑧ 泄漏矩阵门:创建失败/销毁后零工件(进程/凭据/worktree/放置/流);TTFT 双指标探针;克隆摘要门

2 · 剪除的机器(及其替代)

✂ 持久日志引擎抽取 + 逐效果 prepared/committed 回执 → 效果全部可观测(workspace 在不在、worktree 在不在、pane 活没活), 启动 reconcile 直接拿现实对 PLAN 核账;注册表 = 单 JSON 文件 + 现成 writeFileAtomic。数十实例,O(实例) 自动成立。
✂ bootInstance 三模式框架 → 两个 async 函数(ensure server / spawn pane);半成品创建一律回滚重来(Q4 整次原则), recoverAttempt 模式随之消失;golden 的 resume 见证复用现成 rotation/rebind 机械。
✂ 凭据 generation/在途合并/claimed 记账/15min 租约 → 同 key 重试到未认领行 = 轮换新 token(旧作废,一行 CAS); 并发同 key POST = 409 稍后重试;丢 token = destroy + 重建(受信本地,调用方就是 owner 自己的工具)。
✂ SESSION SKU 全套(park/resume/stopped 态/park 凭据语义)→ v1 只有 RUN:create → dispatch → destroy。 状态 = creating → active → destroyed | failed,四个,完。
✂ 实例内编排 RPC → v1 单 agent 无内部编排;缝留作一段文档说明的扩展点(团队版=扩展不重写)。
✂ 1/100/10k 鉴权门、G8 词禁门、100MB/聚合帽探针矩阵 → 发布门的尺寸帽已构造性排除大输入;规模门随规模来。

3 · 创建流程(全文)

POST /api/instances {manifestDigest, idempotencyKey}       [flag 开 + owner principal]
 1 PLAN     预分配全部 id;manifest 校验(恰一 terminal · finality='native' · goldenClone 就位)
 2 INTENT   注册表落 {plan, key, 请求指纹} (writeFileAtomic)
 3 EFFECTS  mint(存hash) → workspace(预分配id) → worktree(按 SHA detach,禁hook,失败=回滚)
            → clone(§1-④,摘要校验) → ensure server + spawn pane(async) → verify(克隆绑定+watch就位)
 4 ACTIVE   注册表更新 → 201 {instanceId, entryAgentId, token}
失败任意一步:回滚(v5 原语序)→ failed 行含失败相;清不掉的留 cleanup 债 + owner 事件 + 退避重试。
重启 reconcile:creating 行 = 现实对 PLAN 核账后整体回滚;active 行 = 重建放置(实例 pane fail-closed 属权)。
重试同 key:active 未认领 → 轮换 token 返回;failed → 重放失败;不同指纹 → 409。
